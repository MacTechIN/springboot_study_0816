스프링 부트 3 프로젝트 구조 설명서

웹 브라우저의 요청부터 컨트롤러, 서비스, 리포지토리, 데이터베이스로 이어지는 계층형 아키텍처 흐름 및 핵심 도구를 한눈에 이해합니다.

스프링 부트 요청 처리 및 계층 흐름 (Request Processing Flow)

Step 2

1. TestController 클래스

Controller Layer
"TestController 클래스는 외부 요청을 분기하여 적절한 서비스 클래스와 연결하여 작업을 처리하고 값을 다시 반환해요."

웹 브라우저의 HTTP 요청(`/test`)을 가장 먼저 수신합니다. 어떤 요청인지 판단하고, 실질적인 작업을 실행하기 위해 `TestService` 클래스에 다음 작업을 요청합니다.

2. TestService 클래스

Service Layer
"TestService 클래스는 데이터베이스 조작이나 비즈니스 로직을 메서드 기반으로 처리해요."

컨트롤러로부터 전달받은 요청을 전달받아 그 요청에 맞는 작업(비즈니스 로직)을 수행합니다. 필요한 경우 `MemberRepository`를 호출하여 데이터 조작 및 조회를 진행합니다.

3. Member & MemberRepository

Persistence Layer
"Member 클래스로 구현한 클래스를 MemberRepository 인터페이스가 실제 테이블과 매핑합니다 (JPA, 하이버네이트 덕분!)."

`Member` 클래스는 DB 테이블의 자바 객체 표현(Entity)이며, `MemberRepository` 인터페이스는 실제 데이터베이스의 `Member` 테이블(`NAME` 컬럼 등)과 매핑 및 연결되어 데이터 조작을 전담합니다.

4. h2database

Database Layer
"실질적인 데이터는 h2 데이터베이스에 쌓여요."

애플리케이션 실행 시 메모리에 실질적인 데이터가 저장되는 인메모리(In-Memory) 데이터베이스입니다. 빠르게 개발하고 검증할 수 있는 최적의 환경을 제공합니다.

build.gradle 핵심 개발 도구 (Dependencies)

"build.gradle에 앱 개발에 필요한 도구를 적으면 알아서 로딩해줘요."

JPA (Java Persistence API)

자바 객체와 데이터베이스 테이블 간의 매핑을 자동화하는 ORM 기술로, 데이터베이스 연결 및 CRUD 구현을 획기적으로 손쉽게 해줍니다.

Lombok

자바 클래스 구현 시 반복되는 Getter, Setter, 생성자 코드 등을 어노테이션 기반으로 자동 생성해 주는 구현 도우미 라이브러리입니다.

H2 Engine

별도의 DB 설치 없이 애플리케이션 내부에 임베디드하여 테스트할 수 있는 초경량 인메모리 데이터베이스 엔진입니다.

⚡ 데이터 조회 및 아키텍처 구현 표준 지침

스프링 부트 애플리케이션 개발 시 데이터베이스 성능 최적화와 계층 분리 원칙을 준수합니다.

  • 인풋 페이징 (Cursor/Input-based Paging) 채택: 데이터베이스 조회가 수반되는 목록/게시판 구현 시 전통적인 `OFFSET/LIMIT` 대신 커서 식별자 기반의 인풋 페이징을 적용하여 대용량 데이터 성능을 보장합니다.
  • 단방향 계층 흐름 준수: 웹 브라우저 ➔ Controller ➔ Service ➔ Repository ➔ DB 순으로 요청을 전달하고, 반대 순서로 결과를 반환하여 계층 간 결합도를 최적화합니다.
